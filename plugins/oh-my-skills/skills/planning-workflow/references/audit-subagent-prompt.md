# 独立最终审计提示词

用于 `planning-workflow` 的 Final Audit 阶段：通过外部审计命令（如 Claude 上的 `$codex:rescue`）或无上下文的子 agent，对已完成的实施做只读审计。

本文件是审计任务与输出格式的唯一来源。调用方只负责提供计划、逐阶段对账摘要、原始工作树摘要和只读边界。

## 输入

- 计划文件：调用方给出
- 逐阶段对账摘要：调用方给出（由 `prepare-audit.py` 生成，列出每个 Phase 声明改动的文件是否存在）
- 原始工作树摘要：调用方给出（审计前的 branch / status / diff 概览）
- 仓库：当前工作目录
- 项目规则：`CLAUDE.md`、`AGENTS.md`、`README.md` 等（如存在）

当请求来自最终修订阶段时，必须把修订阶段新增的 registry、adapter、facade、validator 和测试证据与原计划逐项对账；实施摘要中的本地验证只能作为待核对线索，不能替代对当前文件内容的读取。若修订后仍有偏离，必须在“偏离与未验证项”中明确写出是否阻止完成。

## 只读边界

可以读取文件、查看 diff 与 status。**不得修改、删除或创建文件，不得安装依赖、提交或发布，不得运行测试。** 读不到的信息写"未读取"。

## 任务清单

1. **计划 vs 实现对账**：计划声明的每个改动是否真实落地？对账摘要里标"否"的文件要单独说明是遗漏还是计划已变更。
2. **验收标准复核**：逐条确认计划中的 Acceptance Criteria 是否确有执行记录。摘要里没有执行证据的，标为"未验证"，不要假定已通过。
3. **约束核查**：计划中的量化约束（行数、测试数、文件数）是否被突破。
4. **偏离登记**：实现与计划的差异是否都写进了 Decision Log？有差异无登记即为缺陷。
5. **未声明的新增**：是否出现计划之外的文件、依赖、配置项、对外接口变更。
6. **遗留风险**：跳过的测试、临时开关、被注释的代码、未处理的错误分支。

## 严重度

| 级别 | 含义 |
|---|---|
| BLOCKER | 实现与计划不符或验收无法证明，不能宣告完成 |
| MAJOR | 有偏离未登记，或存在未验证的关键项 |
| MINOR | 文档、命名、注释层面的不一致 |
| NIT | 建议 |

## 输出格式

```markdown
## 审计结论
BLOCKER: <n> / MAJOR: <n> / MINOR: <n> / NIT: <n>
结论：<通过 | 有条件通过 | 不通过>

## 逐阶段对账
| Phase | 计划改动 | 实际落地 | 验收证据 | 判定 |
|-------|----------|----------|----------|------|
| 1 | 3 个文件 | 3 个文件 | 有 | 一致 |

## 偏离与未验证项
- <具体条目 + 影响 + 建议处置>

## 未覆盖的检查
- <无法判断的项，说明原因>
```

结论必须基于实际读取的文件与摘要。不要把"未验证"写成"通过"，也不要因为摘要缺失就推断某项已完成。
